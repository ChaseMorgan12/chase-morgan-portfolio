Sprint four has come and past and with it came a lot of good progress towards the final product including an alpha build. A lot of the time spent during the sprint was related to an upcoming collectible system to be implemented inside the game to give the player a sense of accomplishment. That system had a lot of moving parts that all needed to be implemented for the system to work the way we wanted it to, which increased how long it took dramatically.

Collectibles was a feature that was in the original vision for this game, so it needed to be added accordingly to that vision. The entire system is all on the back end which sprint five will be focused on making that system visible to the player and interactable. The idea was to have a star system where the player will earn one star for each level, but that star will be either bronze, silver, gold, or diamond depending on what is done in the level. Each level will have three different sub-levels with each being harder than the latter. If the player does all objectives, they will receive a gold star for that sub-level. If the player gets a gold star for each sub-level, the level's stars will turn diamond signifying that the player has mastered that entire level. There also another system that is a physical collectible that the player has to touch to unlock which won't be present in all levels but will be neat little things to grab if seen. A new system was put into place to help make this feature happen which stores the data from a level into a serializable format and saves it to disc. It stores everything about a level, if it has been completed, the stars earned in integer format, if the player has the collectible (if there is one), and the level ID to make sure it applies the data to the correct level. It's a lot of moving parts but was made a lot easier using the EventBus programming pattern which ties events to an enumerator and triggers methods if that event ever happens.

Another big accomplishment during this sprint was a new redefined level selection system as the last one didn't even work and was not scalable at all. This new system sees how many levels are in the game at start and builds the level selection screen with pages based on how many there are. Under the hood it uses a LinkedList for the pages which means that it isn't contiguous in memory (like a standard array/List) and each element stores a reference to the next and last element which allows easy page creation for UI. The system does a for loop at the start through the list of levels and displays it on the page the level should be listed under. This allows the system to build the exact number of levels select buttons for the number of levels in the game. So, if levels are added (or even removed) the system will display every level that is offered to the player in an easy to navigate manner.

Shader programming was also something that was worked on during this sprint including two custom shaders that will ease the workflow of textures being made. One takes the texture given and translates it to world space which is similar to how a tri-planar texture works, but the texture also tiles appropriately to the global scale of the object. Another shader that was made is a tri-planar grid shader that efficiently writes a grid texture in world space that covers the level so the player knows at what increments their portal will snap to. This shader also works independently of how the level is laid out so it doesn't matter how the level is made; the shader will conform to it.

Everything else during the sprint were small things that mostly included bug fixes and QoL improvements. Next sprint will focus on using the data from our alpha playtest to make the game as easy to use as possible to hopefully appeal towards a more casual demographic. Everything is going smoothly and hopefully it will stay that way!
